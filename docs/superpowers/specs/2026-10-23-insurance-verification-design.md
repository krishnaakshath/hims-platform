# Insurance verification and pre-authorisation (WS12): design

**Date:** 2026-10-23 · **Status:** approved under the owner's standing instruction · **Parent:** `docs/superpowers/specs/2026-10-23-hospital-completion-design.md` (sub-project 2) · **Findings:** `docs/superpowers/plans/2026-10-23-gap-closure-plan.md` K3, K5–K8, K10, L1–L4, L7–L9, I6, I7 · **Plan:** `docs/superpowers/plans/2026-10-23-insurance-verification.md`

## 1. Intent

Make cashless insurance work end to end: every cover check is saved with who, when, source and the limits returned; insurers not on NHCX get a manual verification record; the policy's validity and the latest verification are checked at policy add, OPD check-in, IPD admission and pre-auth creation; sub-limits reach the charge rules and the estimate; a wrong-person ABHA cannot be linked silently; pre-auths stop failing for reasons the user cannot see. Live NHCX/ABDM credentials do not exist, so everything runs and is tested in the labelled mock (`ABDM_USE_MOCKS=1`, not production) and says "Not configured" honestly otherwise.

## 2. What exists today (verified in the tree)

- `nhcx_eligibility_checks` stores status and `inforce` only (`src/lib/queries/nhcx-eligibility.ts`, `src/lib/nhcx/inbound.ts` `processInboundFhir`). `parseEligibilityResponse` (`src/lib/fhir/nhcx/eligibility.ts`) reads `insurance[0].inforce` and nothing else. The mock answer (`synthesizeMockResponse`) returns `inforce: true` with no limits.
- `EligibilityCheckPanel` polls a check and forgets it; a reload shows nothing.
- `patient_policies` has `valid_from/valid_to`, `sum_insured_paise`, `copay_bp`, `room_rent_limit_paise`; `valid_to` is enforced only by the NHCX eligibility `prepare()`. `createPreauth` and check-in ignore it. There is no ICU limit.
- The legacy `insurance_eligibility_checks` table and `/api/front-desk/eligibility-check` (410) are US-era and stay untouched.
- ABHA link (`/api/patients/[anonId]/abha/link`, `applyVerifiedAbha`) never compares the ABDM profile with the chart. `AbhaFlow.verified` keeps number/address only. Scan & Share `resolveShare('linked')` has the same gap.
- Pre-auth request events freeze a `PreauthSnapshot`; `createPreauthExchange` reads the snapshot's payer codes while `preauthNhcxState` reads live data, so the page says "can send" and the send fails with "no NHCX participant code" (K6/K7).
- `PreauthForm` defaults the treating doctor to `doctors[0]` and disables submit with no explanation.
- `/rcm/settings` (admin) saves ROHINI/HFR with no message; `useRcmAction` only refreshes.
- Admission is the inpatient branch of `POST /api/front-desk/check-in` (`checkInVisit` in `src/lib/queries/encounters.ts`); no payer, policy, pre-auth or deposit is captured.

## 3. Decisions (rulings where the gap analysis is silent)

| # | Ruling | Reason |
|---|---|---|
| R1 | One append-only table, `coverage_verifications`, holds every verification result from any source (`nhcx`, `nhcx_mock`, `manual`). NHCX rows are written by the callback inside the same transaction that settles `nhcx_eligibility_checks`. | One place to read "current cover" for header, tabs, check-in, admission, pre-auth and charge rules; append-only keeps the history auditable. |
| R2 | A verification is **current** until `valid_until`. NHCX/mock results: `verified_at + 24 h` (`COVERAGE_FRESH_HOURS`). Manual: staff choose a date, default today + 7 days IST, at most today + 30, never after the policy's `valid_to`. | Manual confirmations from a TPA desk are typically good for the episode; NHCX is cheap to re-run. |
| R3 | Policy validity is **computed**, never written: no cron flips `status`. `policy_expired` = `valid_to < today IST`; `policy_not_started` = `valid_from > today`. | Avoids a background job and keeps `status` as the staff-set flag. |
| R4 | Severity by context: OPD check-in and registration **never block** (warn, suggest self-pay); IPD admission in `cashless` mode **blocks** on expired / not-started / inactive policy or a current `inactive` verification, **warns** on unverified / stale / error; an `emergency` admission downgrades every block to a warning. Pre-auth creation blocks on a policy not in force on the planned date or a current `inactive` verification. No admin override on an expired policy: the honest path is self-pay or fixing the dates. | Care is never refused at the OPD desk; cashless only where the insurer will pay. |
| R5 | Auto eligibility: at policy add (when a doctor is known: the provider of the patient's latest non-cancelled encounter), at OPD check-in, at IPD cashless admission and at pre-auth creation, an NHCX check is **started after commit** when NHCX is available (configured or mock), the payer is on NHCX and no current active verification exists. It never delays or fails the parent action; the response says whether a check started or why it was skipped. | The insurer answers asynchronously; the badge picks the result up. |
| R6 | Limits returned by NHCX are read from `CoverageEligibilityResponse.insurance[0]`: `benefitPeriod.end`, `item[].benefit[]` (`type` `benefit` → sum insured `allowedMoney`, balance = allowed − `usedMoney`; `copay-percent` → `allowedUnsignedInt` × 100 bp), and items whose `category` code is `room-rent` / `icu` → per-day limits. The item/category codes are **UNVERIFIED U20** against the NRCeS profile and are listed in `docs/ABDM-NHCX.md`. The mock returns fixed, labelled values. Response identifiers are stored as `insurer_reference` (≤ 64 chars), never logged; `NhcxResponseSummary` stays free of references. | Honest about what is not yet confirmed with a live insurer. |
| R7 | Effective limits = the current verification's values where given, else the policy's own fields. `patient_policies` gains `icu_limit_paise`. ICU limit applies when the room category code is in `ICU_ROOM_CATEGORY_CODES` (`ICU`, `HDU`, `NICU`, `PICU`, `CCU`). | Staff-entered policy limits remain useful without NHCX. |
| R8 | Two new charge rules, appended last: `room_rent_over_limit` and `sum_insured_exceeded`, default **warn**, configurable, not overridable. The estimate shows an **indicative** insurer/patient split (co-pay, room-rent excess × days, excess over balance) without proportionate-deduction maths. | Billing must see the risk; the insurer's adjudication remains the truth. |
| R9 | ABHA identity guard compares name, date of birth and gender server-side. Name: lower-case, strip honorifics (`mr mrs ms miss dr smt shri sri kumari km master baby`) and punctuation, tokens compared as sets; an initial matches a token starting with it only when at least one full token also matches; anything else is a mismatch. DOB: ABDM year (and month/day when present) against the chart; gender `M/F/O` ↔ `male/female/(transgender|other)`. A field ABDM did not give, or a chart `unknown`/null, is `unavailable` (shown, not a mismatch). Any mismatch needs an override reason (10–300 chars) stored in `abha_link_overrides`; audit details carry field names only. A flow without a stored profile (created before deploy) counts as a name mismatch. | K3: a wrong-person link must be a conscious act. |
| R10 | Pre-auth "Refresh snapshot" is a new lifecycle action `refresh_snapshot` (allowed in `requested` and `enhancement_requested`, status unchanged) that appends a new event with a fresh snapshot. Refused when the latest snapshot already went to NHCX (outbound exchange in any state other than `send_failed`/`error`) or nothing changed (same SHA-256). `createPreauthExchange` sends the latest of `request`/`request_enhancement`/`refresh_snapshot`. | Events are append-only (SP7 trigger); a new event preserves what was sent before. |
| R11 | `preauthNhcxState` compares the snapshot with live data and explains a stale snapshot ("saved before the insurer's NHCX code / the hospital IDs were added: refresh the snapshot, then send"). Every NHCX panel calls `router.refresh()` after any failed or final action so the server state is recomputed (K6). | The fix for K6 is recomputation, not caching changes. |
| R12 | Admission insurance lives in a new table `admission_coverage` (one row per admission), written inside the check-in transaction via a hook on `checkInVisit`, and editable later through `PUT /api/admissions/[id]/coverage`. `admissions` itself is not changed (the IPD sub-project owns it). Deposit is captured as `deposit_required_paise` (self-pay default = `billing_settings.ipd_deposit_threshold_paise`, cashless default 0) with a "Collect deposit" link to the Cash Desk; money is collected through the existing ledger only. | No overlap with WS3's admission form; one payment path. |
| R13 | ROHINI/HFR stay admin-editable. The RCM area shows a notice to every RCM user when either is missing: admins get a link to `/rcm/settings`, others "Ask an administrator". Save shows "Saved" with what the IDs unlock. | K5 without widening a legal-identifier write to more roles. |
| R14 | "Simulate ABHA share" is a route and button that exist only when ABDM is in mock mode (`readAbdmConfig().state === 'mock'`); otherwise the route answers 404 after the role and body checks. It writes an ordinary `abdm_profile_shares` row with `is_mock = true`, optionally copying a chosen patient's name/DOB/gender (to test the match path) or taking typed values (to test the mismatch path). | K10, demo-able without a signed ABDM callback. |
| R15 | Dashboard tiles (L9) on `/rcm`: policies expiring in 7 days, today's admissions without a current verification, claims blocked by missing hospital identifiers. | Cheap, uses the new tables. |

Out of scope: live NHCX/ABDM onboarding, TPA-portal deep links and credential vault, PM-JAY/CGHS/ECHS verification, card OCR/QR (L5, L6), ABHA-linked policy discovery (L7 second half), ward/gender validation and the rest of the admission form (WS3).

## 4. Data model (migrations `scripts/migrations/2026-10-24-ws12-*.sql`)

**`coverage_verifications`** (append-only; trigger `ws12_coverage_verifications_append_only`, bypassed only under `hims.allow_document_purge = 'on'`):
`id serial PK`, `patient_id text FK patients`, `policy_id int FK patient_policies`, `source text` (`nhcx` | `nhcx_mock` | `manual`), `result text` (`active` | `inactive` | `error`), `context text` (`registration` | `checkin` | `admission` | `preauth` | `manual`), `nhcx_check_id int UNIQUE NULL FK nhcx_eligibility_checks`, `method text NULL` (`insurer_portal` | `tpa_portal` | `phone` | `email` | `letter`; required when manual), `insurer_reference text NULL` (≤ 64), `document_blob_url text NULL`, `document_sha256 text NULL`, `document_content_type text NULL` (all three or none), `verified_by_name text NOT NULL`, `verified_by_user_id int NULL FK users`, `verified_at timestamp NOT NULL`, `valid_until timestamp NOT NULL` (> verified_at), `sum_insured_paise bigint NULL`, `balance_paise bigint NULL`, `copay_bp int NULL` (0–10000), `room_rent_limit_paise bigint NULL`, `icu_limit_paise bigint NULL`, `reported_valid_to date NULL`, `note text NULL` (≤ 500), `created_at timestamp`. Indexes `(policy_id, verified_at DESC)`, `(patient_id)`. Amount checks 0–10¹².

**`admission_coverage`**: `admission_id int PK FK admissions`, `mode text` (`self_pay` | `cashless` | `reimbursement`), `policy_id int NULL FK`, `preauth_id int NULL FK`, `deposit_required_paise bigint NOT NULL DEFAULT 0`, `coverage_state text NOT NULL` (the verdict state when recorded), `verification_id int NULL FK coverage_verifications`, `override_note text NULL`, `recorded_by_name`, `recorded_by_user_id`, `recorded_at`, `updated_at`. Checks: self_pay ⇒ policy and preauth null; otherwise policy not null; deposit 0–10¹⁰.

**`abha_link_overrides`** (append-only): `id`, `patient_id FK`, `via text` (`abha_flow` | `scan_and_share`), `share_id int NULL FK abdm_profile_shares`, `fields jsonb` (array of `name` | `dob` | `gender`), `reason text` (10–300), `by_name`, `by_user_id`, `at`.

**Changes:** `patient_policies.icu_limit_paise bigint NULL` (check 0–10¹²); `nhcx_eligibility_checks_context_valid` re-created to allow `checkin` (`ELIGIBILITY_CONTEXTS` gains it); enum `preauth_action` gains `refresh_snapshot` (own enum-only migration, as `2026-10-08-sp5-lab-enum-values.sql` does).

## 6. Error handling

- New RCM errors: `policy_not_in_force` (422, "This policy is not valid on <date> (valid <from>–<to>)"), `coverage_inactive` (409, "The last verification says this policy is not in force"). Check-in answers 409 `{ code: 'coverage_blocked', state }` before any room is claimed. ABHA link and share resolve answer 409 `{ code: 'identity_mismatch', fields }`.
- Upload without a storage driver answers the Foundations `storage_not_configured` body; the verification row is not written.
- NHCX unavailable: badges read "NHCX not configured: record a manual verification"; nothing pretends to have checked. Mock results carry "Sandbox mock - not real" everywhere they show.
- Logs carry error class names only; audit details carry ids, enum values and paise, never names, ABHA numbers, references, reasons or blob URLs.

## 7. Testing

Pure unit tests for the evaluator, estimate split, identity comparison, form helper and the extended response parser; DB-backed tests (isolated `hims_test` only) for the callback writing verifications, manual verification, check-in/admission gating, pre-auth refresh/send and charge rules; component tests for badge, dialogs, form messages and the identity warning; RBAC rows for every new route; a Docker walkthrough in mock mode (Task 12).
